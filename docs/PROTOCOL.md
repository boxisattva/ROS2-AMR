## 1. Общие положения

### 1.1 Scope
Этот документ определяет формат кадров, передаваемых между:
- **Master:** Ноутбук (Ubuntu 22.04, ROS2 Humble, пакет `amr_base_control`)
- **Slave:** ESP32 WROOM-32 (FreeRTOS, прошивка `amr_controller`)

### 1.2 Физический уровень
| Параметр | Значение | Примечание |
|----------|----------|------------|
| Интерфейс | USB-UART (мост CP2102) | `/dev/ttyUSB0` на ноутбуке |
| Baud rate | 115200 | Максимальная надёжная скорость для Dupont-проводов ~20 см |
| Data bits | 8 | |
| Stop bits | 1 | |
| Parity | None | Контроль чётности заменён на XOR-checksum в кадре |
| Flow control | None | RTS/CTS не используются |

### 1.3 Принцип human-readable
Протокол **текстовый** (ASCII). Это позволяет:
- Отлаживать через `minicom -D /dev/ttyUSB0 -b 115200`
- Читать логи без hex-дампа
- Добавлять новые типы сообщений без изменения бинарной структуры

## 2. Байтовая структура кадра (BNF)
<<frame><type><arg><arg><checksum><terminator><type><digit><arg><integer><float><string><integer><digit><digit><float><digit><digit><digit><digit><string><letter><digit><checksum><terminator>

### 2.1 Ограничения
- Максимальная длина кадра: **64 байта** (включая `$` и `\n`)
- Максимальное количество аргументов: **6**
- Разделитель аргументов: **запятая** `,` (0x2C)
- Нет пробелов внутри кадра (кроме строковых аргументов, если специально оговорено)

## 3. Алгоритм контрольной суммы (Checksum)

### 3.1 Определение
**Checksum** — XOR (побитовое исключающее ИЛИ) всех байтов между символами `$` (не включая) и `*` (не включая).

Результат записывается как **двузначный HEX** в верхнем регистре (00..FF).

### 3.2 Псевдокод (C++ / ESP32)

```cpp
uint8_t calculateChecksum(const char* data, size_t len) {
    uint8_t cs = 0;
    for (size_t i = 0; i < len; ++i) {
        cs ^= static_cast<uint8_t>(data[i]);
    }
    return cs;
}

// Использование:
// data = "VEL,0.25,0.0"
// cs = 0xA3

### 3.3 Псевдокод (Python/ROS2)

def calculate_checksum(data: str) -> str:
    """
    data: строка между $ и *, например "VEL,0.25,0.0"
    возвращает: двузначный hex в верхнем регистре, например "A3"
    """
    cs = 0
    for ch in data:
        cs ^= ord(ch)
    return f"{cs:02X}"

### 3.4 Проверка на приёме (ESP32)

bool validateFrame(const String& frame) {
    int starIdx = frame.indexOf('*');
    if (starIdx < 0) return false;
    
    String payload = frame.substring(1, starIdx);      // без '$' и '*'
    String csStr = frame.substring(starIdx + 1, starIdx + 3);
    
    uint8_t expectedCs = static_cast<uint8_t>(strtol(csStr.c_str(), nullptr, 16));
    uint8_t actualCs = calculateChecksum(payload.c_str(), payload.length());
    
    return expectedCs == actualCs;
}

## 4. Типы сообщений: Ноутбук → ESP32 (Master → Slave)

### 4.1 $VEL — Задание скорости
| Поле        | Тип   | Диапазон     | Единица | Описание                       |
| ----------- | ----- | ------------ | ------- | ------------------------------ |
| `linear_x`  | float | \[-0.5, 0.5] | м/с     | Линейная скорость вперёд/назад |
| `angular_z` | float | \[-1.0, 1.0] | рад/с   | Угловая скорость (поворот)     |

Формат: $VEL,<linear_x>,<angular_z>*<<CS>\n
Пример: $VEL,0.25,0.0*A3\n — ехать вперёд 0.25 м/с, без поворота.
Согласование с ROS2:

Источник: топик /cmd_vel (geometry_msgs/Twist)
Конвертация: amr_base_control/serial_bridge.cpp извлекает msg.linear.x и msg.angular.z, масштабирует под диапазон и формирует кадр.

### 4.2 $LED — Управление индикацией
| Поле   | Тип | Диапазон | Описание                                        |
| ------ | --- | -------- | ----------------------------------------------- |
| `mode` | int | 0..4     | Режим: 0=off, 1=green, 2=red, 3=blue, 4=rainbow |
| `r`    | int | 0..255   | Красный (только для mode=custom, резерв)        |
| `g`    | int | 0..255   | Зелёный                                         |
| `b`    | int | 0..255   | Синий                                           |

Формат: $LED,<mode>,<r>,<g>,<b>*<<CS>\n
Пример: $LED,2,0,0,0*C1\n — красный свет (режим 2).

### 4.3 $BUZ — Звуковой сигнал

| Поле          | Тип | Диапазон | Единица | Описание                                            |
| ------------- | --- | -------- | ------- | --------------------------------------------------- |
| `freq`        | int | 0..5000  | Гц      | Частота звука. 0 = выключить                        |
| `duration_ms` | int | 0..5000  | мс      | Длительность. 0 = бесконечно (до следующей команды) |

Формат: $BUZ,<freq>,<duration_ms>*<<CS>\n
Пример: $BUZ,1000,200*E7\n — писк 1 кГц, 200 мс.

### 4.4 $STO — Emergency Stop

Формат: $STO*<<CS>\n
Пример: $STO*5A\n
Поведение ESP32:

PWM всех моторов → 0
Сброс целевой скорости
LED → красный мигающий (если не переопределено)

### 4.5 $PING — Проверка связи

Формат: $PING*<<CS>\n
Пример: $PING*43\n
Ответ ESP32: $PONG,<uptime_ms>*<<CS>\n

## 5. Типы сообщений: ESP32 → Ноутбук (Slave → Master)

### 5. 5.1 $ODO — Одометрия

| Поле      | Тип   | Диапазон     | Единица | Описание                                  |
| --------- | ----- | ------------ | ------- | ----------------------------------------- |
| `v_left`  | float | \[-1.0, 1.0] | м/с     | Скорость левого колеса (расчётная по PWM) |
| `v_right` | float | \[-1.0, 1.0] | м/с     | Скорость правого колеса                   |
| `dt_ms`   | int   | 10..1000     | мс      | Время с последнего кадра                  |

Формат: $ODO,<v_left>,<v_right>,<dt_ms>*<<CS>\n
Пример: $ODO,0.24,0.24,100*7B\n
Согласование с ROS2:

    amr_base_control/serial_bridge.cpp парсит кадр
    Публикует nav_msgs/Odometry в топик /odom
    dt_ms используется для интегрирования позиции (дед-рекoning)

Примечание: Без энкодеров v_left/v_right — это расчётные значения из PWM и калибровочных коэффициентов. См. ADR-006 в ARCHITECTURE.md.

### 5.2 $STA — Статус системы

| Поле         | Тип | Диапазон | Описание                      |
| ------------ | --- | -------- | ----------------------------- |
| `state`      | int | 0..2     | 0=OK, 1=WARN, 2=ERR           |
| `error_code` | int | 0..255   | Код ошибки (см. таблицу ниже) |

Формат: $STA,<state>,<error_code>*<<CS>\n
Пример: $STA,0,0*2F\n — всё в порядке.
	Таблица error_code:
| Код | Значение          | Описание                            |
| --- | ----------------- | ----------------------------------- |
| 0   | NONE              | Нет ошибки                          |
| 1   | BAD\_FRAME        | Невалидный кадр (checksum mismatch) |
| 2   | UNKNOWN\_CMD      | Неизвестный тип сообщения           |
| 3   | OUT\_OF\_RANGE    | Аргумент вне допустимого диапазона  |
| 4   | MOTOR\_FAULT      | Проблема с драйвером моторов        |
| 5   | WATCHDOG\_TIMEOUT | Сработал fail-safe (потеря связи)   |

### 5.3 $PONG — Ответ на PING

| Поле        | Тип | Диапазон | Единица | Описание                        |
| ----------- | --- | -------- | ------- | ------------------------------- |
| `uptime_ms` | int | 0..2^32  | мс      | Время с момента включения ESP32 |

Формат: $PONG,<uptime_ms>*<<CS>\n
Пример: $PONG,124500*9A\n

### 5.4 $ERR — Сообщение об ошибке (verbose)

| Поле          | Тип    | Описание                                    |
| ------------- | ------ | ------------------------------------------- |
| `code`        | int    | Код ошибки (как в \$STA)                    |
| `description` | string | Человекочитаемое описание (max 20 символов) |


Формат: $ERR,<code>,<description>*<<CS>\n
Пример: $ERR,1,BAD_FRAME*D4\n

## 6. Примеры кадров с hex-дампом

### 6.1 $VEL,0.25,0.0*A3

ASCII:  $  V  E  L  ,  0  .  2  5  ,  0  .  0  *  A  3  \n
HEX:   24 56 45 4C 2C 30 2E 32 35 2C 30 2E 30 2A 41 33 0A
LEN:   17 байт

Расшифровка:

    $ — начало кадра
    VEL — тип: задание скорости
    0.25 — linear_x = 0.25 м/с
    0.0 — angular_z = 0.0 рад/с
    *A3 — checksum (XOR "VEL,0.25,0.0" = 0xA3)
    \n — конец кадра

Проверка XOR:
V(0x56) ^ E(0x45) ^ L(0x4C) ^ ,(0x2C) ^ 0(0x30) ^ .(0x2E) ^ 2(0x32) ^ 5(0x35) ^ ,(0x2C) ^ 0(0x30) ^ .(0x2E) ^ 0(0x30) = 0xA3

### 6.2 $STO*5A

ASCII:  $  S  T  O  *  5  A  \n
HEX:   24 53 54 4F 2A 35 41 0A
LEN:   8 байт

Расшифровка: Emergency stop. Checksum XOR("STO") = 0x5A.

### 6.3 $ODO,0.24,0.24,100*7B

ASCII:  $  O  D  O  ,  0  .  2  4  ,  0  .  2  4  ,  1  0  0  *  7  B  \n
HEX:   24 4F 44 4F 2C 30 2E 32 34 2C 30 2E 32 34 2C 31 30 30 2A 37 42 0A
LEN:   22 байта

### 6.4 Невалидный кадр (bad checksum)

$VEL,0.25,0.0*FF\n

ESP32 должен игнорировать кадр и отправить $ERR,1,BAD_FRAME*D4.

## 7. Согласование с архитектурой amr_base_control

### 7.1 ROS2 → UART (TX, ноутбук → ESP32)

┌─────────────────┐     ┌──────────────────────────┐     ┌─────────────┐
│   /cmd_vel      │     │  amr_base_control        │     │   UART TX   │
│  Twist.msg      │────▶│  serial_bridge.cpp       │────▶│  $VEL,...   │
│  linear.x       │     │  - subscribe /cmd_vel    │     │  /dev/ttyUSB0│
│  angular.z      │     │  - scale to [-0.5,0.5]   │     │  115200 baud │
└─────────────────┘     │  - format frame          │     └─────────────┘
                        │  - calc checksum         │
                        │  - write to serial      │
                        └──────────────────────────┘


Mapping:
| ROS2 поле   | Тип     | UART поле   | Правило конвертации                   |
| ----------- | ------- | ----------- | ------------------------------------- |
| `linear.x`  | float64 | `linear_x`  | clamp(-0.5, 0.5), round(2)            |
| `angular.z` | float64 | `angular_z` | clamp(-1.0, 1.0), round(2)            |
| `linear.y`  | —       | —           | Игнорируется (2WD, нет движения вбок) |
| `linear.z`  | —       | —           | Игнорируется                          |


### 7.2 UART → ROS2 (RX, ESP32 → ноутбук)

┌─────────────┐     ┌──────────────────────────┐     ┌─────────────────┐
│   UART RX   │     │  amr_base_control        │     │   /odom         │
│  $ODO,...   │────▶│  serial_bridge.cpp       │────▶│  Odometry.msg   │
│  /dev/ttyUSB0│     │  - read line             │     │  pose.x,y,theta │
│  115200 baud │     │  - validate checksum     │     │  twist.x,z      │
└─────────────┘     │  - parse frame           │     └─────────────────┘
                    │  - integrate odometry    │
                    │  - publish /odom          │
                    └──────────────────────────┘

Mapping:
| UART поле | ROS2 поле         | Правило конвертации                      |
| --------- | ----------------- | ---------------------------------------- |
| `v_left`  | `twist.linear.x`  | (v\_left + v\_right) / 2                 |
| `v_right` | `twist.angular.z` | (v\_right - v\_left) / wheel\_separation |
| `dt_ms`   | —                 | Используется для интегрирования позы     |

## 8. Поведение парсера (State Machine)

### 8.1 Диаграмма состояний (ESP32)

┌─────────┐    '$'     ┌──────────┐    ',' или '*'   ┌─────────┐
│  IDLE   │───────────▶│  TYPE    │──────────────────▶│  ARGS   │
│         │            │  (A-Z)   │                  │         │
└─────────┘            └──────────┘                  └────┬────┘
     ▲                                                   │
     │                      '\n'                         │
     │    ┌──────────────────────────────────────────────┘
     │    │
     │    ▼
     └────┴──▶ [validate checksum] ──OK?──▶ [dispatch] ──▶ DONE ──▶ IDLE
              │
              FAIL
              │
              ▼
         [send $ERR] ──▶ IDLE

### 8.2 Правила парсера

Начало кадра: ждём $. Всё до $ — мусор (возможен noise при старте).
Тип: последовательность заглавных букв/цифр. Максимум 8 символов.
Аргументы: после первой , — набор значений, разделённых ,.
Конец полезной нагрузки: *.
Checksum: 2 hex-символа после *.
Терминатор: \n (0x0A). Если пришёл \r (0x0D) — игнорировать или трактовать как часть мусора.
Таймаут кадра: если от $ до \n прошло > 50 мс — сбросить в IDLE. Это предотвращает «зависание» на половине кадра.

## 9. Fail-safe и таймауты

### 9.1 Watchdog на стороне ESP32

| Параметр       | Значение               | Действие                             |
| -------------- | ---------------------- | ------------------------------------ |
| Таймаут связи  | 500 мс                 | Если нет валидного кадра > 500 мс    |
| Действие       | Моторы → STOP          | PWM = 0                              |
| Индикация      | LED → красный мигающий | 2 Гц                                 |
| Восстановление | Автоматическое         | При получении любого валидного кадра |

### 9.2 Частота обмена

| Направление              | Рекомендуемая частота | Максимальная частота |
| ------------------------ | --------------------- | -------------------- |
| Ноутбук → ESP32 (`$VEL`) | 10 Гц (100 мс)        | 50 Гц                |
| ESP32 → Ноутбук (`$ODO`) | 10 Гц (100 мс)        | 50 Гц                |
| ESP32 → Ноутбук (`$STA`) | 1 Гц (1 с)            | 5 Гц                 |

Расчёт bandwidth:

    Кадр $VEL ≈ 17 байт. При 10 Гц = 170 байт/с ≈ 1.36 кбит/с.
    Кадр $ODO ≈ 22 байта. При 10 Гц = 220 байт/с.
    Итого: ~400 байт/с << 115200 baud (≈ 14 кбайт/с). Запас > 30×.
